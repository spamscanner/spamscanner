# 보안과 개인정보

Spam Scanner는 비공개 데이터인 메일을, 적대적일 수 있는 발신자로부터 받아 읽습니다. 이 페이지에서는 Spam Scanner가 외부로 보내는 모든 것과, 읽은 내용을 다루는 방식을 설명합니다.


## 컴퓨터 밖으로 나가는 데이터

기본적으로는 한 가지뿐입니다. 메시지에 있는 **링크의 호스트 이름**을 Cloudflare의 필터링 리졸버에서 조회합니다. 1.1.1.2와 1.0.0.2(악성코드와 피싱), 1.1.1.3과 1.0.0.3(성인 콘텐츠 포함)입니다. 이는 `example.com` 같은 이름에 대한 일반 DNS 조회이며, 메시지나 주소의 어떤 부분도 전송하지 않습니다. `phishing: {cloudflare: false}` 또는 `--no-cloudflare`로 끌 수 있고, 성인 콘텐츠 검사만 끄려면 `phishing: {adult: false}`를 사용합니다.

그 밖의 모든 것은 설정하기 전까지 꺼져 있습니다.

| 검사                  | 보내는 데이터                                                  | 받는 곳                                       |
| ------------------- | -------------------------------------------------------- | ------------------------------------------ |
| `authentication`    | 발신자의 SPF, DKIM, DMARC, ARC 레코드에 대한 DNS 조회                | 사용 중인 리졸버 또는 `dnsServers`                  |
| `dnsbl`             | 뒤집은 클라이언트 IP 주소와 링크 도메인을 담은 DNS 조회                       | 사용 중인 리졸버나 `dns.servers`를 거쳐 차단 목록의 네임 서버로 |
| `llm`               | 메시지 요약(원격 제공자에게는 개인 데이터를 제거하고 보냄)                        | 지정한 언어 모델 서버([개인정보 보호](llm.md#privacy))    |
| `reputation.apiUrl` | 클라이언트의 IP 주소와 확인된 호스트 이름, From·봉투 발신자·Reply-To 주소와 그 도메인 | 지정한 서비스                                    |
| `clamav`            | 첨부 파일                                                    | 소켓을 통해 사용 중인 clamd로                        |

원격 측정, 업데이트 확인, 실행 중 다운로드는 없습니다. 모델은 패키지 안에 포함되어 배포됩니다.


## 보관하는 데이터

요청하지 않는 한 아무것도 보관하지 않습니다. 검사는 기록하거나 저장하지 않습니다. `learn()`은 메모리에 있는 분류기를 변경하며, 디스크에는 `saveModel()`, `spamscanner learn`, 또는 서버의 `--out` 옵션으로만 기록됩니다. 모델 파일에는 단어나 메시지 텍스트가 아니라 해시된 특징 개수가 들어 있습니다.

언어 모델의 답변은 보낸 내용의 해시를 키로 메모리에 캐시되므로, 같은 메시지가 반복해서 와도 한 번만 묻습니다. DNS 응답은 10분 동안, 평판 서비스의 응답은 5분 동안(`reputation.cacheTtl`, 실패한 요청은 1분) 메모리에 캐시됩니다.


## 적대적인 입력

* 첨부 파일은 바이트로 식별하며, 실행하거나 다른 프로그램으로 열지 않습니다. ZIP 압축 파일은 중앙 디렉터리에서 읽으며, 항목 수(2000개)와 항목 이름의 바이트 수(1 MiB. 1 KiB를 넘는 이름은 처음과 마지막 512바이트만 남기며, 발견 사항에는 이름을 최대 100자만 표시합니다)에 제한을 두고, 각 항목은 몇 개의 디렉터리가 가리키든 한 번만 읽습니다. 아무것도 압축을 풀지 않으므로, 중첩되거나 압축된 압축 파일 안의 프로그램은 보이지 않습니다. 첨부된 메시지(`message/rfc822`, 또는 파일 이름이 `.eml`로 끝나는 첨부 파일)는 세 단계 깊이까지 열며, 그 첨부 파일은 최대 100개, 첨부된 메시지는 모두 합쳐 25 MB까지입니다. 메시지 자체의 첨부 파일은 항상 모두 검사합니다. MIME 파서의 한도(파트 1000개 초과, 또는 한 파트의 헤더 1 MB 초과)를 넘는 메시지는 파서가 허용하는 만큼(앞쪽 파트들, 그리고 발신자가 계속 반영되도록 줄인 너무 큰 헤더) 읽고 `MIME_TOO_COMPLEX`를 받으며, 이는 어떤 감점으로도 상쇄되지 않습니다. ClamAV는 그 메시지 전체를 읽습니다. 파서가 읽지 못한 첨부된 메시지도 이를 받으며, 검사를 실패시키지 않습니다. 주소 필드는 각각 최대 16 KB(주소 2000개, 중첩 그룹 16개), 메시지마다 모두 합쳐 64 KB까지 읽으며, 온전한 주소의 끝에서만 자릅니다. 주소 파서가 걸리는 시간이 주소 수의 제곱에 비례해 늘어나기 때문입니다. mailauth도 From과 Return-Path는 이렇게 제한된 대로 읽으며(다른 필드는 그대로 읽으므로 그 필드에 대한 서명은 유효합니다), 읽는 데 선형 시간보다 오래 걸릴 헤더(접힌 줄 수천 개, 또는 수천 개의 필드를 지정하는 서명)는 줄여서 읽습니다. From 필드가 잘리면 DMARC에 실패하며 어떤 허용 목록에도 해당하지 않습니다. HTML은 Spam Scanner 자체 파서가 아무리 깊이 중첩되어 있어도 선형 시간에 읽습니다.
* 본문 텍스트는 `maxLength`(100,000자)까지만 읽으며, 서버는 25MB까지의 메시지를 받습니다. 링크는 `phishing.maxLength`(1,000,000자)까지 읽습니다.
* 모든 네트워크 검사에는 제한 시간(`timeout`, 기본 10초)이 있습니다. 실패하거나 시간이 초과된 검사는 건너뛰고, 그 검사 없이 검사를 마칩니다. 인증과 이미지 모델(처음 10개 이미지)은 각각 전체가 이 시간 안에 끝납니다. 인증은 이 시간이 지나면 DNS 쿼리를 보내지 않고, 한 메시지에 300개보다 많이 보내지도 않으며(RFC 7208의 한도에 이른 SPF와 DKIM, ARC, DMARC, BIMI를 위한 여유), 메시지의 처음 8개 DKIM 서명만 검사합니다(mailauth 자체는 ARC 세트를 최대 50개까지 읽습니다). milter가 추가하는 `Authentication-Results` 헤더에는 최대 8 KiB의 결과가 담깁니다. ClamAV(한 번에 첨부 파일 4개)에는 메시지의 모든 첨부 파일에 대한 별도의 제한(`clamav.timeout`, 60초)이 있으며, 검사하지 못한 첨부 파일은 `results.virusScanErrors`에 나열됩니다. 언어 모델에는 별도의 시간 제한(`llm.timeout`)이 있습니다.
* 허용 목록은 발신자가 위조할 수 없는 것만 신뢰합니다. 클라이언트의 주소와 확인된 호스트 이름, 그리고 인증으로 확인된 발신자 도메인입니다. [허용 목록과 차단 목록](api.md#allowlist-and-denylist)
* 메시지에 이미 있는 `X-Spam-*` 헤더는 milter, 콘텐츠 필터, `--headers`가 제거하므로, 발신자가 자기 메일을 정상으로 표시할 수 없습니다.
* Microsoft의 스팸 판정 헤더는 메시지가 Microsoft 서버에서 직접 왔을 때만 신뢰하며, Received 헤더는 메시지의 출처를 판단하는 데 결코 쓰지 않습니다.
* AI 필터를 겨냥한 텍스트는 스팸으로 점수가 매겨지며, 언어 모델에는 메시지가 지시가 아니라 데이터라고 알려 줍니다. [프롬프트 인젝션](llm.md#prompt-injection)


## 서버

milter, HTTP, TCP, spamd 서버는 `--host`로 달리 지정하지 않는 한 127.0.0.1에서 수신합니다. HTTP API는 토큰을 상수 시간으로 비교하며, 토큰이 없으면 `/learn`을 거부합니다. 어느 서버도 TLS를 지원하지 않습니다. 네트워크를 거쳐 접속하려면 사설 네트워크, SSH 터널, 또는 TLS를 쓰는 리버스 프록시를 사용하십시오.

권한이 없는 사용자로 실행하십시오. [Postfix 가이드의 systemd 유닛](postfix.md#1-run-the-milter)에는 일반적인 보안 강화 설정이 들어 있습니다.
