# 测试与分值

邮件达到 5 分即为垃圾邮件，达到 15 分即被拒收。下面每项测试都会加分或减分；结果会列出触发的测试。`rejectThreshold` 低于 `threshold` 时，只拒绝垃圾邮件。

用 `threshold` 和 `rejectThreshold` 修改阈值。用 `scores` 修改分值，既可以按设置键（`scores: {deceptiveLink: 4}`），也可以按测试名称，后者会固定该测试的分值（`scores: {FROM_NAME_BRAND: 4}`）。


## 分类器

| 测试                       | 分值           | 含义                                                                                                                                                                                                              |
| ------------------------ | ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `BAYES_00` 到 `BAYES_999` | -2.5 到 +6.25 | 分类器的垃圾邮件概率，按对数几率换算：90% 时为 2.4 分，99% 时为 5 分，99.9% 时为 6.25 分，因此分类器只有在至少 99% 确定时才会单独判定为垃圾邮件。名称表示所在区间：`BAYES_999` 为 99.9% 或以上，`BAYES_99` 为 99% 到 99.9%，`BAYES_50` 为 40% 到 60%。设置键 `bayesHam` 和 `bayesSpam` 设定两端的分值。 |

## 身份验证

需要客户端的 IP 地址和 `authentication: true`。

| 测试             |   分值 | 设置键（在 `authentication.weights` 中）    |
| -------------- | ---: | ------------------------------------ |
| `SPF_PASS`     | -0.5 | `spfPass`                            |
| `SPF_FAIL`     |    2 | `spfFail`                            |
| `SPF_SOFTFAIL` |    1 | `spfSoftfail`                        |
| `DKIM_PASS`    | -0.5 | `dkimPass`                           |
| `DKIM_FAIL`    |    1 | `dkimFail`                           |
| `DMARC_PASS`   | -1.5 | `dmarcPass`                          |
| `DMARC_FAIL`   |  3.5 | `dmarcFail`（策略为 quarantine 或 reject） |
| `DMARC_FAIL`   |    1 | `dmarcFailNone`（策略为 none）            |
| `ARC_PASS`     | -0.5 | `arcPass`                            |
| `ARC_FAIL`     |    1 | `arcFail`                            |

DMARC 记录按 RFC 7489 的方式读取，不论其空格和大小写（`p= None` 即 `none`，`adkim=S` 即严格），并强制执行严格对齐：在 `adkim=s` 下，只有 From 域名本身的签名才算对齐，在 `aspf=s` 下，只有其 SPF 通过才算对齐，因此只满足宽松对齐的邮件 DMARC 失败。没有恰好一个 From 地址的邮件（两个地址、两个 From 字段、一个组、只出现在编码字中的地址，或根本没有 From），mailauth 不检查其 DMARC，这类邮件按 RFC 7489（第 6.6.1 节）所允许的那样，以策略未知判定 DMARC 失败。

DMARC 失败按域名的策略计分：域名要求隔离或拒绝失败的邮件，或策略未知时，计满分，此时 SPF 同时失败不再额外加分（不计 `SPF_FAIL` 和 `SPF_SOFTFAIL`），因为 DMARC 已经计入了它。策略为 `none` 时，域名并不为其失败负责，因此 `DMARC_FAIL` 分数很小，但 SPF 的分数会叠加在其上：策略为 `none` 的域名绝不会比没有 DMARC 的域名更容易被冒充（SPF 以 `-all` 失败：没有 DMARC 时 2 分，策略为 `none` 时 3 分，quarantine 或 reject 时 3.5 分）。一封未经 SRS 转发、又被添加了破坏签名的页脚的邮件，最多得 3.5 分，而不是 5.5 分。

只签署正文开头部分的 DKIM 签名（正文长度 `l=` 短于正文：任何人都能在其后追加文字）不会得到 `DKIM_PASS`，仅依赖这种签名、没有对齐的 SPF 的 DMARC 通过也不会得到 `DMARC_PASS`。

转发方（例如邮件列表）可以用 ARC 封印为其收到的内容作担保。任何人都能封印邮件，因此只有来自你在 `authentication.trustedArcSealers` 中指定的转发方的封印才计入（域名涵盖其子域名），而且只有当最新的 ARC 组由该域名封印（其 ARC-Seal 和 ARC-Message-Signature 属于同一域名），且其封印的结果表明邮件在它收到时已通过时才计入：From 域名的 DMARC，或可注册域名相同的域名的 DKIM 或 SPF。这样的邮件（`authentication.arc.trusted`）会得到 `ARC_PASS`，且不会因 SPF、DKIM 或 DMARC 失败而得分，也不算 `SELF_SPOOF`（列表成员写信给自己域名的列表）；其他任何 ARC 通过都不得分，不受信任或失败的封印仍会得到 `SELF_SPOOF`。通过 `authenticationResults` 传入的结果不信任任何转发方。

```js
new SpamScanner({authentication: {trustedArcSealers: ['lists.example.org']}});
```


## 信誉和黑名单

| 测试             |  分值 | 设置键           | 含义                           |
| -------------- | --: | ------------- | ---------------------------- |
| `DENYLISTED`   | 100 | `denylisted`  | 发件人的 IP 地址、域名或地址在拒绝列表上       |
| `ALLOWLISTED`  | -20 | `allowlisted` | 客户端，或经身份验证确认的发件人，在允许列表中      |
| `TRUTH_SOURCE` |  -5 | `truthSource` | 信誉服务将发件人标记为可信                |
| `RBL_<LIST>`   |   4 | `rblListed`   | 客户端的 IP 地址在黑名单上，例如 `RBL_ZEN` |
