# การทดสอบและคะแนน

ข้อความถือเป็นสแปมที่ 5 คะแนน และถูกปฏิเสธที่ 15 คะแนน การทดสอบแต่ละรายการด้านล่างจะเพิ่มหรือลดคะแนน ผลลัพธ์แสดงรายการที่ทำงาน `rejectThreshold` ที่ต่ำกว่า `threshold` จะปฏิเสธเฉพาะสแปม

เปลี่ยนเกณฑ์ด้วย `threshold` และ `rejectThreshold` เปลี่ยนคะแนนด้วย `scores` โดยระบุด้วยคีย์การตั้งค่า (`scores: {deceptiveLink: 4}`) หรือด้วยชื่อการทดสอบ ซึ่งจะกำหนดคะแนนของการทดสอบนั้นตายตัว (`scores: {FROM_NAME_BRAND: 4}`)

| -------------------------- | -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `BAYES_00` ถึง `BAYES_999` | -2.5 ถึง +6.25 | ความน่าจะเป็นของสแปมจากตัวจำแนก บนสเกล log-odds: 2.4 คะแนนที่ 90% 5 คะแนนที่ 99% และ 6.25 คะแนนที่ 99.9% ตัวจำแนกจึงตีว่าเป็นสแปมด้วยตัวเองก็ต่อเมื่อมั่นใจอย่างน้อย 99% ชื่อบอกช่วงค่า: `BAYES_999` คือ 99.9% ขึ้นไป `BAYES_99` คือ 99% ถึง 99.9% `BAYES_50` คือ 40% ถึง 60% คีย์การตั้งค่า `bayesHam` และ `bayesSpam` กำหนดค่าทั้งสองปลาย |

You should join us") และจะไม่นับเลยเมื่ออยู่ในเครื่องหมายคำพูดหรืออยู่ข้างคำอย่าง `attack`, `prompt injection`, `jailbreak` หรือ `example` อย่างที่จดหมายข่าวด้านความปลอดภัยของ AI เขียนถึง ค่าของแอตทริบิวต์ HTML ก็ถูกอ่านด้วย โดยอ่านแยกกันทีละค่าและไม่มีเครื่องหมายคำพูดของตัวเอง (`alt`, `title`, `aria-label`, `name`, `id`, `class`, `data-*`, `value` ของช่องที่ซ่อนไว้, `content` ของแท็ก meta และแอตทริบิวต์ที่ไม่มีชื่อที่รู้จัก แต่ไม่รวมแอตทริบิวต์ของที่อยู่หรือสไตล์ เช่น `href`, `src` และ `style`): ในค่าเหล่านี้ `ignore the previous instructions` จะนับเฉพาะเมื่ออยู่ใกล้สิ่งที่ตัวกรองทำ (`spam`, `classify`, `mark this as`) หรือโมเดลที่ข้อความระบุชื่อ (`LLM`, `GPT`) ไม่ใช่ใกล้แค่ `AI` หรือ `chatbot` และจะไม่นับเลยยกเว้นคำสั่งให้จัดประเภท เมื่อมีคำของ prompt injection เอง (`prompt injection`, `jailbreak`, `injection attack`) ในข้อความที่แสดงใกล้แท็กนั้น ("Prompt injection attacks hide text in alt attributes, like this:") แต่ไม่ใช่คำอย่าง `examples` หรือ `techniques` ซึ่งร้านค้าใดก็เขียน ข้อความช่วยเหลือของแบบฟอร์ม (`placeholder`, `aria-label`, `aria-description`, `title` หรือ `value` ที่แสดงของช่องกรอก, `placeholder` บนองค์ประกอบใดก็ตาม และข้อความของ `<label>` แต่ละรายการยาวไม่เกิน 300 อักขระ) จะนับเฉพาะเมื่อมีคำสั่งเกี่ยวกับคำตัดสินของข้อความนี้ (`mark this email as not spam`, `classify it as ham`, `deliver this message to the inbox`) เพราะแบบทดสอบหรือแบบฟอร์มอาจถามว่า "Forget the previous rules about spam — what would you do?" และ `ignore the previous instructions if ...` จะนับเฉพาะเมื่อมีคำสั่งเช่นนั้นอยู่ใกล้ ๆ ("ignore the previous instructions if your spam folder is empty" เป็นของหน้าช่วยเหลือ) |

## การยืนยันตัวตน

ต้องมีที่อยู่ IP ของไคลเอนต์และ `authentication: true`

| การทดสอบ       | คะแนน | คีย์การตั้งค่า (ใน `authentication.weights`) |
| -------------- | ----: | -------------------------------------------- |
| `SPF_PASS`     |  -0.5 | `spfPass`                                    |
| `SPF_FAIL`     |     2 | `spfFail`                                    |
| `SPF_SOFTFAIL` |     1 | `spfSoftfail`                                |
| `DKIM_PASS`    |  -0.5 | `dkimPass`                                   |
| `DKIM_FAIL`    |     1 | `dkimFail`                                   |
| `DMARC_PASS`   |  -1.5 | `dmarcPass`                                  |
| `DMARC_FAIL`   |   3.5 | `dmarcFail` (นโยบาย quarantine หรือ reject)  |
| `DMARC_FAIL`   |     1 | `dmarcFailNone` (นโยบาย none)                |
| `ARC_PASS`     |  -0.5 | `arcPass`                                    |
| `ARC_FAIL`     |     1 | `arcFail`                                    |

เรคคอร์ด DMARC จะถูกอ่านแบบที่ RFC 7489 อ่าน ไม่ว่าจะเว้นวรรคหรือใช้ตัวพิมพ์ใหญ่เล็กแบบใด (`p= None` คือ `none` และ `adkim=S` คือแบบเข้มงวด) และมีการบังคับใช้ความสอดคล้องแบบเข้มงวด: ภายใต้ `adkim=s` จะสอดคล้องเฉพาะลายเซ็นของโดเมน From เองเท่านั้น และภายใต้ `aspf=s` จะสอดคล้องเฉพาะการผ่าน SPF ของโดเมนนั้นเท่านั้น ดังนั้นข้อความที่ผ่านเพียงความสอดคล้องแบบผ่อนปรนจะล้มเหลว DMARC ข้อความที่ไม่มีที่อยู่ From เพียงหนึ่งเดียวพอดี (มีสองที่อยู่ มีฟิลด์ From สองฟิลด์ เป็นกลุ่ม มีที่อยู่อยู่ใน encoded word เท่านั้น หรือไม่มี From เลย) ซึ่ง mailauth ไม่ตรวจ DMARC ให้ จะล้มเหลว DMARC โดยถือว่าไม่ทราบนโยบาย ตามที่ RFC 7489 (ส่วนที่ 6.6.1) อนุญาต

ความล้มเหลวของ DMARC ให้คะแนนตามนโยบายของโดเมน: เต็มจำนวนเมื่อโดเมนขอให้กักกันหรือปฏิเสธข้อความที่ล้มเหลว หรือเมื่อไม่ทราบนโยบาย และความล้มเหลวของ SPF ที่เกิดร่วมด้วยจะไม่เพิ่มคะแนนอีก (ไม่นับ `SPF_FAIL` และ `SPF_SOFTFAIL`) เพราะ DMARC นับไว้แล้ว เมื่อนโยบายเป็น `none` โดเมนไม่ได้รับผิดชอบความล้มเหลวของตัวเอง `DMARC_FAIL` จึงมีค่าน้อย แต่คะแนนของ SPF จะนับเพิ่มเข้าไปด้วย: โดเมนที่มีนโยบาย `none` จะไม่มีทางปลอมแปลงได้ง่ายกว่าโดเมนที่ไม่มี DMARC (SPF ล้มเหลวด้วย `-all`: 2 คะแนนเมื่อไม่มี DMARC, 3 คะแนนเมื่อมีนโยบาย `none` และ 3.5 คะแนนเมื่อเป็น quarantine หรือ reject) ข้อความที่ถูกส่งต่อโดยไม่มี SRS และถูกเพิ่มส่วนท้ายที่ทำให้ลายเซ็นเสีย จะได้ไม่เกิน 3.5 คะแนน ไม่ใช่ 5.5

ลายเซ็น DKIM ที่ลงนามเฉพาะส่วนต้นของเนื้อความ (ความยาวเนื้อความ `l=` สั้นกว่าเนื้อความ: ใครก็เพิ่มข้อความต่อท้ายได้) จะไม่ได้ `DKIM_PASS` และการผ่าน DMARC ที่อาศัยลายเซ็นแบบนั้นเพียงอย่างเดียว โดยไม่มี SPF ที่สอดคล้อง ก็จะไม่ได้ `DMARC_PASS`

ผู้ส่งต่อ เช่น เมลลิงลิสต์ สามารถรับรองสิ่งที่ได้รับด้วยตราประทับ ARC ใครก็ประทับตราข้อความได้ ตราประทับจึงนับเฉพาะจากผู้ส่งต่อที่คุณระบุใน `authentication.trustedArcSealers` (โดเมนครอบคลุมโดเมนย่อยของตัวเอง) และเฉพาะเมื่อชุด ARC ล่าสุดถูกประทับตราโดยโดเมนนั้น (ARC-Seal และ ARC-Message-Signature ของชุดนั้นมาจากโดเมนเดียวกัน) และผลลัพธ์ที่โดเมนนั้นประทับตราไว้แสดงว่าข้อความผ่านเมื่อโดเมนนั้นได้รับ: DMARC สำหรับโดเมน From หรือ DKIM หรือ SPF ของโดเมนที่มีโดเมนที่จดทะเบียนได้เดียวกัน ข้อความแบบนั้น (`authentication.arc.trusted`) จะได้ `ARC_PASS` และไม่ได้คะแนนจากความล้มเหลวของ SPF, DKIM หรือ DMARC และไม่ถือเป็น `SELF_SPOOF` (สมาชิกลิสต์ที่เขียนถึงลิสต์ในโดเมนของตัวเอง) ส่วนการผ่าน ARC แบบอื่นจะไม่ได้อะไรเลย และตราประทับที่ไม่น่าเชื่อถือหรือล้มเหลวยังคงได้ `SELF_SPOOF` ผลลัพธ์ที่ส่งมาใน `authenticationResults` ไม่เชื่อถือผู้ส่งต่อใดเลย

```js
new SpamScanner({authentication: {trustedArcSealers: ['lists.example.org']}});
```
