# テストとスコア

メッセージは5点でスパム、15点で拒否になります。以下の各テストが点数を加算または減算し、結果には該当したテストが示されます。`rejectThreshold` が `threshold` より低い場合、拒否されるのはスパムだけです。

しきい値は`threshold`と`rejectThreshold`で変更します。点数は`scores`で変更します。設定キーで指定する方法（`scores: {deceptiveLink: 4}`）と、テスト名で指定してそのテストの点数を固定する方法（`scores: {FROM_NAME_BRAND: 4}`）があります。


## 分類器

| テスト                    | 点数         | 意味                                                                                                                                                                                                    |
| ---------------------- | ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `BAYES_00`〜`BAYES_999` | -2.5〜+6.25 | 分類器のスパム確率を対数オッズの尺度で表したもの。90%で2.4点、99%で5点、99.9%で6.25点のため、分類器単独でスパムとするのは99%以上の確信がある場合だけです。名前が区間を示します。`BAYES_999`は99.9%以上、`BAYES_99`は99%〜99.9%、`BAYES_50`は40%〜60%です。設定キー`bayesHam`と`bayesSpam`で両端を設定します。 |

`MIME_TOO_COMPLEX` を付けるのは、MIME パーサーのこの 2 つの上限と、パーサーが失敗する添付されたメッセージだけです。それ以外のパーサーエラーはスキャンを失敗させ、サーバーは以前のバージョンと同じくメッセージを延期します。パートが多すぎるメッセージは、パートを開始しうる行（`--`）の 990 行目まで読みます。インラインの添付されたメッセージがパートを構成する場合は、読めるようになるまで前半、次に 4 分の 1 と読みます。メッセージ自体のヘッダーが大きすぎる場合は、そのヘッダーを切り詰めて読みます（1 行最大 998 文字、1 フィールド最大 8 KB とし、それでも 512 KB を超える場合は、誰がどのように送ったかを示すフィールドだけにします）。そのため送信者は引き続き評価されます。後続のパートのヘッダーが大きすぎる場合は、その最初の 1 MB を読みます。ClamAV はメッセージ全体を読みます。これを相殺できるのは `ALLOWLISTED` と `TRUTH_SOURCE` だけです。その他のクレジット（ベイズの ham、SPF、DKIM、DMARC、ARC、言語モデルの ham）はこのメッセージでは何の効果もありません。読まれなかった部分は保証できないからです。

## 認証

クライアントのIPアドレスと`authentication: true`が必要です。

| テスト            |   点数 | 設定キー（`authentication.weights`内）       |
| -------------- | ---: | ------------------------------------- |
| `SPF_PASS`     | -0.5 | `spfPass`                             |
| `SPF_FAIL`     |    2 | `spfFail`                             |
| `SPF_SOFTFAIL` |    1 | `spfSoftfail`                         |
| `DKIM_PASS`    | -0.5 | `dkimPass`                            |
| `DKIM_FAIL`    |    1 | `dkimFail`                            |
| `DMARC_PASS`   | -1.5 | `dmarcPass`                           |
| `DMARC_FAIL`   |  3.5 | `dmarcFail`（ポリシーがquarantineまたはreject） |
| `DMARC_FAIL`   |    1 | `dmarcFailNone`（ポリシーがnone）            |
| `ARC_PASS`     | -0.5 | `arcPass`                             |
| `ARC_FAIL`     |    1 | `arcFail`                             |

DMARCレコードは、空白や大文字・小文字にかかわらず、RFC 7489のとおりに読みます（`p= None`は`none`、`adkim=S`は厳格）。厳格なアラインメントも適用します。`adkim=s`ではFromドメインそのものの署名だけが、`aspf=s`ではそのドメインのSPF合格だけがアラインするため、緩やかなアラインメントしか満たさないメッセージはDMARCに失敗します。Fromアドレスがちょうど1つではなく（アドレスが2つ、Fromフィールドが2つ、グループ、エンコードされたワードの中にだけあるアドレス、またはFromがまったくない）、mailauthがDMARCを検査しないメッセージは、RFC 7489（6.6.1節）が認めるとおり、ポリシー不明としてDMARCに失敗します。

DMARCの失敗は、ドメインのポリシーに応じて点数が付きます。ドメインが失敗の隔離または拒否を求めている場合、またはポリシーが不明な場合は満点で、SPFも失敗していてもそれ以上何も加わりません（`SPF_FAIL`と`SPF_SOFTFAIL`は除かれます）。DMARCがすでにそれを数えているためです。ポリシーが`none`の場合、そのドメインは自らの失敗に責任を持たないため`DMARC_FAIL`は小さくなりますが、SPFの点数はそれに上乗せされます。ポリシーが`none`のドメインが、DMARCのないドメインよりなりすましやすくなることはありません（`-all`でSPFが失敗した場合、DMARCなしで2点、ポリシー`none`で3点、quarantineまたはrejectで3.5点）。SRSなしで転送され、署名を壊すフッターが追加されたメッセージは、5.5点ではなく最大3.5点になります。

本文の先頭だけに対するDKIM署名（本文長`l=`が本文より短いもの。その後には誰でもテキストを追加できます）は`DKIM_PASS`を得られず、アラインしたSPFなしにそれだけに基づくDMARCの合格は`DMARC_PASS`を得られません。

メーリングリストなどの転送者は、受け取った内容をARCシールで保証できます。シールは誰でも付けられるため、`authentication.trustedArcSealers`で指定した転送者のシールだけが使われます（ドメインはそのサブドメインも対象にします）。それも、最新のARCセットがそのドメインによってシールされ（ARC-SealとARC-Message-Signatureが同じドメインのもの）、シールされた結果が、転送者が受け取った時点でメッセージが合格していたことを示している場合に限ります。つまり、FromドメインのDMARC、または登録可能ドメインが同じドメインのDKIMかSPFです。そのようなメッセージ（`authentication.arc.trusted`）は`ARC_PASS`を得て、SPF、DKIM、DMARCの失敗による点数を受けず、`SELF_SPOOF`にもなりません（リストのメンバーが自分のドメインのリストに書く場合）。それ以外のARCの合格には何も付かず、信頼されていないシールや失敗したシールでは引き続き`SELF_SPOOF`になります。`authenticationResults`で渡された結果は、どの転送者も信頼しません。

```js
new SpamScanner({authentication: {trustedArcSealers: ['lists.example.org']}});
```
