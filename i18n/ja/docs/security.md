# セキュリティとプライバシー

Spam Scannerが読むのは、私的な内容であるメールで、その送信者は敵対的な場合があります。このページでは、Spam Scannerがどこに何を送るか、そして読んだものをどう扱うかを説明します。


## マシンの外に出るもの

デフォルトでは1つだけです。メッセージ内の**リンクのホスト名**を、Cloudflareのフィルタリング用リゾルバーである1.1.1.2と1.0.0.2（マルウェアとフィッシング）、1.1.1.3と1.0.0.3（アダルトコンテンツも対象）で照会します。これは`example.com`のような名前に対する通常のDNSクエリで、メッセージやそのアドレスの一部が送られることはありません。無効にするには`phishing: {cloudflare: false}`または`--no-cloudflare`を、アダルトコンテンツの検査だけを無効にするには`phishing: {adult: false}`を使います。

それ以外はすべて、設定するまで無効です。

| 検査                  | 送るもの                                                            | 送り先                                         |
| ------------------- | --------------------------------------------------------------- | ------------------------------------------- |
| `authentication`    | 送信者のSPF、DKIM、DMARC、ARCレコードに対するDNSクエリ                            | 自分のリゾルバー、または`dnsServers`                    |
| `dnsbl`             | 逆順にしたクライアントのIPアドレスとリンクのドメイン（DNSクエリとして）                          | ブロックリストのネームサーバー（自分のリゾルバーまたは`dns.servers`経由） |
| `llm`               | メッセージの要約（リモートのプロバイダーには個人データを削除して送る）                             | 指定した言語モデルのサーバー（[プライバシー](llm.md#privacy)）    |
| `reputation.apiUrl` | クライアントのIPアドレスと検証済みホスト名、およびFrom・エンベロープ送信者・Reply-Toのアドレスとそれらのドメイン | 指定したサービス                                    |
| `clamav`            | 添付ファイル                                                          | 自分のclamd（ソケット経由）                            |

テレメトリー、更新の確認、実行時のダウンロードは一切ありません。モデルはパッケージに含まれています。


## 保持するもの

求められない限り、何も保持しません。スキャンはログに記録も保存もされません。`learn()`はメモリ上の分類器を変更するだけで、ディスクに書き込まれるのは`saveModel()`、`spamscanner learn`、サーバーの`--out`オプションを使った場合だけです。モデルファイルが保持するのはハッシュ化した特徴の件数で、単語やメッセージのテキストは含みません。

言語モデルの回答は、送った内容のハッシュをキーとしてメモリにキャッシュされるため、同じメッセージの複製について問い合わせるのは1回だけです。DNSの回答は10分間、レピュテーションサービスの回答は5分間（`reputation.cacheTtl`。失敗したリクエストは1分間）メモリにキャッシュされます。


## 敵対的な入力

* 添付ファイルはバイト列で識別し、実行したり別のプログラムで開いたりすることはありません。ZIPアーカイブはセントラルディレクトリから読み、エントリ数（2000）とその名前のバイト数（1 MiB。1 KiBを超える名前は先頭と末尾の512バイトを残し、検出結果に示すのは1つの名前につき最大100文字）に上限を設けています。各エントリは、いくつのディレクトリが指していても一度だけ読みます。何も展開しないため、入れ子になったアーカイブや圧縮されたアーカイブの中のプログラムは見えません。添付されたメッセージ（`message/rfc822`、またはファイル名が `.eml` で終わる添付ファイル）は 3 階層まで開かれ、その添付ファイルは最大 100 個、添付されたメッセージは合計 25 MB までです。メッセージ自体の添付ファイルは常にすべて検査します。MIME パーサーの上限（1000 を超えるパート、または 1 MB を超えるパートのヘッダー）を超えるメッセージは、パーサーが許す範囲まで読み（最初のほうのパートを、大きすぎるヘッダーは送信者が引き続き評価されるよう切り詰めて読みます）、`MIME_TOO_COMPLEX` を付けます。これはどのクレジットでも相殺されません。ClamAV はメッセージ全体を読みます。パーサーが失敗する添付されたメッセージにもこれを付け、スキャンを失敗させることはありません。アドレスフィールドは、それぞれ 16 KB（2000 アドレス、入れ子のグループ 16 段）まで、メッセージごとに合計 64 KB まで読み、完全なアドレスの終わりでのみ切ります。アドレスパーサーにかかる時間はアドレス数の 2 乗に比例して増えるためです。mailauth も From と Return-Path はこの範囲で読み（ほかのフィールドはそのまま読むため、それらに対する署名は有効なままです）、読むのに線形時間を超える時間がかかるヘッダー（数千行の折り返し行、または数千のフィールドを挙げる署名）は切り詰めて渡します。切り詰めた From フィールドは DMARC に失敗し、許可リストでは何も許可されません。HTML は Spam Scanner 独自のパーサーで、どれほど深く入れ子になっていても線形時間で読みます。
* 本文のテキストは`maxLength`（100,000文字）まで読み、サーバーは25 MBまでのメッセージを受け付けます。リンクは `phishing.maxLength`（1,000,000 文字）まで読み取られます。
* すべてのネットワーク検査にはタイムアウト（`timeout`、デフォルトは10秒）があります。失敗またはタイムアウトした検査はスキップされ、スキャンはその検査なしで完了します。認証と画像モデル（最初の 10 枚の画像）は、それぞれ全体でこの時間内に終わります。認証はこの時間を過ぎると DNS クエリを送らず、1 通のメッセージにつき 300 件を超えて送ることもありません（RFC 7208 の上限での SPF に、DKIM、ARC、DMARC、BIMI を加えても足りる数です）。また、メッセージの最初の 8 個の DKIM 署名だけを検査します（mailauth 自体が読む ARC セットは最大 50 個です）。milter が追加する `Authentication-Results` ヘッダーに含まれる結果は最大 8 KiB です。ClamAV（一度に 4 つの添付ファイル）には、メッセージのすべての添付ファイルに対する独自の制限（`clamav.timeout`、60 秒）があり、スキャンできなかった添付ファイルは `results.virusScanErrors` に列挙されます。言語モデルには独自のタイムアウト（`llm.timeout`）があります。
* 許可リストが信頼するのは、送信者が偽造できないものだけです。クライアントのアドレスと検証済みホスト名、そして認証で確認された送信者ドメインです。[許可リストと拒否リスト](api.md#allowlist-and-denylist)
* メッセージにすでにある`X-Spam-*`ヘッダーは、milter、コンテンツフィルター、`--headers`が削除するため、送信者が自分のメールを問題なしと偽ることはできません。
* Microsoftのスパム判定ヘッダーは、メッセージがMicrosoftのサーバーから直接届いた場合にだけ信頼します。また、メッセージがどこから来たかの判断にReceivedヘッダーを使うことはありません。
* AIフィルターに宛てたテキストはスパムとして採点し、言語モデルにはメッセージが指示ではなくデータであることを伝えます。[プロンプトインジェクション](llm.md#prompt-injection)


## サーバー

milter、HTTP、TCP、spamdの各サーバーは、`--host`で指定しない限り127.0.0.1で待ち受けます。HTTP APIはトークンを定数時間で比較し、トークンなしの`/learn`は拒否します。どのサーバーもTLSを話しません。ネットワーク越しに接続するには、プライベートネットワーク、SSHトンネル、TLSを使うリバースプロキシのいずれかを使ってください。

サーバーは特権のないユーザーで実行してください。[Postfixガイドのsystemdユニット](postfix.md#1-run-the-milter)には、一般的なハードニングの設定が含まれています。


## 脆弱性の報告

セキュリティの問題は、公開のissueではなく、[GitHubの脆弱性報告](https://github.com/spamscanner/spamscanner/security/advisories/new)から非公開で報告してください。
